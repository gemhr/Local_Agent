# Taste

## Execution workflow
- Once authorized, prefers direct autonomous execution without further confirmation: pushes all changes to main (including user-created docs) with Chinese summaries ("直接push两仓的修改到main，不需要检查，我授权了", "你直接执行吧", "push所有修改到main，中文摘要"). Confidence: 0.9

## Multi-agent pipeline
- Runs a two-model pipeline and explicitly assigns roles: ZCode / DeepSeek as the execution/remediation agent, Codex as the architecture-decision and gate-review agent ("执行 Agent：ZCode / DeepSeek", "You are NOT the architecture decision maker"). Confidence: 0.8
- Prefers staged gate reviews that re-verify from current source, the real Git diff, and actually executed tests rather than trusting handoff claims ("不得直接把 believed closed 当成 PASS"; truth priority: current source / Git diff / executed tests > docs > handoffs). Task specs also mandate that scouts run focused tests and record the exact command and result as evidence ("focused tests have real results", "Record exact command and result"). Confidence: 0.85
- Enforces strict scope discipline in scout/audit stages: writable boundary limited to handoff files only, no production/test/config/index changes, no commit/push/merge, and no architecture decisions — issues are escalated as evidence-tagged decision questions for Codex rather than answered by the scout ("ESCALATION_REQUIRED = YES with exact evidence", "Do not expand scope"). Confidence: 0.85
- Expects every pipeline stage to produce mandated structured handoff files with fixed section structures (scout: 00_task.md + 10_zcode_audit.md; execution: 30_zcode_execution.md) plus a terse final console summary with the exact status fields and a git-safety confirmation, then STOP — no implementation after the audit, no WP2 after execution. Confidence: 0.85
- Execution stages must implement frozen Codex architecture decisions faithfully and never redesign or substitute the agent's own preferences; if a frozen contract proves impossible or contradictory, record evidence, set ARCHITECTURE_ESCALATION_REQUIRED = YES, and stop the affected expansion instead of inventing a replacement. Confidence: 0.85
- In serial cross-repository execution, protects pre-existing working-tree modifications: records them before changing code, never resets/reverts/checkouts-over/stashes/cleans/overwrites them, merges carefully into the current tree, and distinguishes PRE_EXISTING_CHANGE from task-introduced changes (WP1_CHANGE) in the handoff. Confidence: 0.85
- Requires evidence-based validation honesty: never claim a test passed unless actually executed; classify regression failures as pre-existing-at-HEAD vs. introduced by the change (e.g., verified via `git show HEAD:`); keep a running validation process (e.g., pytest) under the session handle and poll until terminal completion, capturing the real terminal result. Confidence: 0.8
- At each pipeline-stage boundary, re-verify repository state from Git before reusing prior knowledge: the user may commit the previous stage's output (including final-gate remediations) between tasks, so in-session file readings and one's own earlier handoff claims cannot be assumed current — check git status/branch and per-file `git log --oneline -1 -- <file>`, and re-read any file changed since the earlier read ("FG-1/FG-2 remediations were applied after my execution report, so I must verify from current source, not my remembered version"). Confidence: 0.8
- Scout/audit handoffs must ground every claim in line-level source evidence: trace call chains hop-by-hop with exact symbols and file:line citations, classify each stage of the path against the mandated taxonomy (e.g., strategy-neutral / baseline-specific / reusable / must-change), and present findings as evidence tables/matrixes (budget matrix, type-mapping matrix, escalation-condition checklist) rather than prose conclusions. Confidence: 0.8
- Execution/continuation stages follow a fix-forward rule: ordinary implementation defects, test mismatches, compatibility bugs, and integration mistakes are fixed directly and verified with the affected regression — no re-escalation or re-gate; ARCHITECTURE_REOPEN_REQUIRED is reserved for fixes that would change frozen architecture/owner/scope/persistent-artifact/lifecycle/strategy-semantics/failure-fallback/Memory/public-compatibility contracts ("FIX THEM DIRECTLY → run affected regression → continue. Do NOT request Regate"). Confidence: 0.85
- On "continue a partial implementation" tasks, re-read the actual partial diff from Git rather than trusting the prior execution report to reflect the working tree, and review the partial work against the frozen decision before expanding it — preserve working code unless tests or source review prove a defect, instead of mechanically finishing TODOs. Confidence: 0.8
- When a stage boundary supersedes an earlier stage's temporary behavior, update the obsolete test expectations to the new contract rather than retaining a temporary boundary just to satisfy old tests ("Do not retain a WP1 temporary boundary merely to satisfy an old test"). Confidence: 0.8
- Runtime accounting and observability must be truthful: charge counters only for operations that actually started (and never conflate dimensions, e.g., BM25 queries are not keyword queries); events/logs/metrics must never carry raw queries, document text, source/model paths, or provider exception bodies; score semantics must not be mislabeled (e.g., raw RRF score presented as normalized relevance); documentation must state current capability truthfully without overclaiming default status (new strategy = "reachable", not "default"). Confidence: 0.8
- After adding a strategy-specific/alternative path, run an explicit baseline-isolation review plus a focused baseline regression as a completion gate (BASELINE_REGRESSION_GATE), proving the unchanged default path keeps its adapter, keyword supplement, rerank, filtering, rewrite, empty/failure semantics, and citation behavior. Confidence: 0.75
- On this Windows environment, inspect Git state and filter/pipe output through the PowerShell tool (Select-Object filtering, Out-File to %TEMP% then read_file for long diffs); plain shell_command runs cmd.exe, which lacks Select-String/Select-Object and mishandles `;` chaining and %TEMP% expansion. Confidence: 0.7
