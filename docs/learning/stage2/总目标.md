## 计划调整结论

**总时长不变**，仍然做到第 25 天，从第 13 天起还有 **13 个学习日**。按每周最多五天计算，大约是两周加三天。

只做三处顺序优化：

1. 第 13 天先补 `Parent Runtime / RunCoordinator`，收口目前分散的 Plan、State、Budget、Registry、Scheduler 和 Executor 所有权。
2. 第 16 天增加 Runtime Event（运行时事件）与 Backpressure（背压），否则后续并行 Tool、RAG 和 Trace 容易继续依赖现有文本流。
3. 第 19 天先建立 Event Journal（事件日志），为第 22 天 Snapshot / Replay（快照与回放）提供基础。

第 14、21～25 天原定主线保持不变。

# 第 15 天：Retry 与 Recovery Policy

### 学习内容

- Retryable Error（可重试错误）分类
- Attempt（尝试次数）
- Exponential Backoff（指数退避）
- Jitter（随机抖动）
- Retry Budget
- Deadline-aware Retry
- 取消优先级
- 幂等性
- 模型、Tool、RAG 重试差异
- Partial Stream（部分流）后的重试风险

### LocalAgent 改造目标

- 建立统一 `RetryPolicy`。
- 使用第 11 天 `max_retries` 与 BudgetLedger 记账。

  - 错误可重试

- 禁止模型客户端、Driver、Parent Runtime 多层嵌套重试。
- 已产生部分流式输出后默认禁止透明重试。
- 有副作用 Tool 没有幂等保证时禁止自动重试。
- 与第 14 天 Circuit Breaker 协同。

### 主要产出

- Retry Policy
- Backoff / Jitter

  - StepStarted
  - ModelStarted
  - ToolStarted
  - OutputDelta
  - StepCompleted
  - RunCompleted

- 客户端断开时取消生产者。
- 并行 Step 事件允许交错，但每个 Step 内保持顺序。
- 不把当前自定义流宣称为标准 SSE。
