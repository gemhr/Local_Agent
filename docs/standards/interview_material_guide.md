# 一、真实性要求

整个回答必须严格区分以下四类内容：

1. 用户真实复现；
2. 源码审查发现；
3. 实施或测试过程中真实发现；
4. 假设构造的 Bad Case。

不得把：

- 假设 Bad Case 写成真实生产事故；
- 未来规划写成已经实现；
- Contract-only 写成 Production Supported；
- Recovery Validation 写成 Automatic Recovery；
- Idempotency 写成 Exactly-once；
- 单机能力包装成分布式能力；
- 测试 Fault Injection 描述成生产 Chaos Platform；
- 未执行测试描述为 PASS；
- 推测出的性能收益描述成真实指标。

如果材料不足以证明某件事，明确写“现有材料无法证明”，不要自行补充项目事实。

你可以使用通用计算机科学、Python、后端、AI Agent 和系统设计知识帮助我理解技术，但必须明确区分：

- “项目真实实现”
- “通用知识解释”
- “合理推论”

不得把通用知识反向写成项目已经实现的能力。
