# 环境核对清单

## 建立对照
每个核对项记录：要求来自哪里、环境值来自哪里、二者是否可比较、结论和缺口。先确认记录对应当前执行，而非开发机或另一轮流水线。

| 核对项 | 判定方法 |
| --- | --- |
| 格式或字段版本 | 用例所需版本与工具声明支持集合或范围比较；不能假定更高版本兼容旧版本 |
| 工具与依赖 | 比较显式声明的兼容约束；只记录版本号而没有约束时，不宣称兼容或不兼容 |
| 特性开关 | 分清开启、关闭、缺失以及记录是否说明默认值；不把缺失当关闭 |
| 必要前置条件 | 核对所需资源、配置和步骤是否有实际回执，不根据名称推定就绪 |

## 形成判断
明确要求在已知能力范围外，可报告不兼容；值缺失、来源不明或范围含义不清，应报告信息不足。明确满足某一项只能证明该项，不能泛化为所有环境条件正确。

若需定位故障，再读相应阶段日志验证“要求不满足 → 动作失败”的关系。若日志提示不同原因，保留反证，转入综合调查而非强行归因环境。

## 补查建议
精确提出缺失字段、需要读取的证据类别及其能解决的问题；避免无依据建议重装全部依赖。输出沿用 DiagnosisReport，引用真实 evidence_id/digest，缺项写入 uncertainties；不要制造工具回执或新增报告字段。
