# CI 失败取证指南

## 取证顺序
先用执行上下文确认目标和证据状态，再读取实际失败阶段的原始日志及回执；随后补读环境记录、用例前置条件和相邻阶段日志。核对这些记录是否来自同一次执行。目录中出现证据并不等于已读取，UNAVAILABLE 也不等于内容为空。

## 分类判据
- PARSER：输入格式、字段结构、解析器能力、首个解析异常和退出状态。检查解析是否真正产出下游可消费数据；字段不支持需要用环境能力与输入要求共同证明。
- COMPARISON：比较输入是否完整，比较器是否实际运行，预期值和实际值是否同一口径。空结果可能是上游未产出，不能单独证明产品结果不一致。
- AUTOMATION：调度、启动、步骤执行、超时及工具回执。检查动作是否成功开始、在哪一步中断；基础设施症状不自动等于产品缺陷。

## 首因与症状
按“前置条件 → 动作 → 产物 → 消费者”画出最短证据链。最早出现的错误只有能够解释下游异常才是首因候选。下游错误早于候选原因、或有独立有效输入时，是需要调查的反证。日志时间相近并不足以证明因果。

## 证据不足
缺日志、版本字段、回执或能力值时，明确缺项及其影响；区分未读取、不可用与读取后没有该字段。提出最小补查，如读取具体阶段回执或补齐能力记录。保留 UNKNOWN/INSUFFICIENT_EVIDENCE，不把常见故障模式当成本次事实。

最终引用沿用工具返回的 evidence_id/digest，不引用本指南来证明业务事实；遵循宿主报告对 SUPPORTED 的额外必要条件。
